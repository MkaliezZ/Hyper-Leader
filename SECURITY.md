# Security and privacy boundaries

- This is a loopback-only, single-local-user application. It is not an authenticated cloud multi-tenant service. Do not publicly expose its port.
- Browser API requests use Host/Origin and Sec-Fetch-Site checks, an HttpOnly SameSite cookie, and CSRF for mutations. Internal DSH calls require a separate per-run secret and a fixed case/space scope; they are not a browser proxy.
- The official DSH SDK owns the model loop. Default shell, general filesystem, working-directory tools, telemetry and unrelated tools are disabled. The plugin additionally guards its exact tool allowlist. These restrictions are not an OS sandbox or a guarantee against dependency/runtime vulnerabilities.
- Every source fetch validates public URL syntax, all resolved DNS addresses and each redirect. The selected address is pinned into the connection lookup. Credentials in source URLs and private/reserved destinations are rejected. HTML is parsed as data, not executed.
- Source storage, access, evidence coverage, publisher identity and eligibility are independent. A manual or official-directory entry does not prove current validity or qualification. RSS and search results are leads until their original details are checked.
- Assets are read by registered IDs, scope and version, with real-path and fingerprint checks. Source revocation/exclusion blocks model reads; changed source scope fences the next DSH session instead of silently retaining a wider model history. Old files and audit records remain subject to their actual retention/access policy.
- Domain Python operations are fixed allowlisted scripts, never a generic command runner. Arbitrary local references in input are rejected; only explicitly registered, scope-checked, actually read source assets can be bound by the host. Document parsing has size/time/decompression limits, but is not a native-code security sandbox.
- Markdown does not execute raw HTML or automatically load remote images. Reports escape user text. HTML downloads are sandboxed by response policy; CSV exports protect formula-leading cells. Untrusted external HTML is never inserted into the app DOM.
- API keys are encrypted locally with AES-GCM, with the encryption key in the same private home. This is not protection against a compromised OS account or someone who can copy the whole home. Settings never return the saved key. The app does not import other projects' credentials or the ambient generic DEEPSEEK_API_KEY.
- Model input still goes to the explicitly configured provider and may cost money. Saving settings makes no model call. A connection probe requires explicit consent. Provider and search-service trust remain the user's responsibility.
- Idempotency keys protect ordinary JSON write requests. Reused keys with changed requests fail closed; interrupted pending operations are not blindly replayed. File re-uploads are separate input versions, not automatically collapsed.
- Stopping a run closes its owned DSH process and aborts owned reads/workers; completed files remain. Restart marks unfinished operations interrupted, not successful. Stopping or removing a source cancels affected operations and subscriptions.
- Program-local tracking is opt-in, bounded source refresh while the process is alive, not OS background scheduling or automatic model analysis. Public submission, login automation, account registration, transactions and publishing are not exposed tools.
- `.local/`, credentials, raw sessions, source inputs, logs, dependency environments and browser caches are excluded from Git. Runtime exports and backups can contain sensitive data and local locators; do not share them without review.

Report suspected vulnerabilities privately to the project owner. Do not attach real credentials, customer files or private logs to public issues.
